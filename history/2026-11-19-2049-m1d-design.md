# M1d 设计决策（需求驱动多轮讨论定案 + 实施蓝图）

## 背景

M1c 收尾完成无阻塞后，主开发者发起 M1d 设计讨论，要求**从需求与功能性出发、多轮提问至设计闭环再开工**。
agent 先以审计级全量阅读 docs/wiki/代码/history/原始讨论记录建立心智模型（基线实测全绿：gate/test_gate/
fmt/clippy/96 测试；隔离实例实验确证 REST/SSE 线缆），再分轮讨论。本条目落档全部裁决；实施蓝图见
[roadmap M1d 实施蓝图](../docs/project/roadmap.md#m1d-实施蓝图)。主旨延续：以用户实际使用需求为核心、
agent 长期工程可行性、重要分歧人工介入、长期稳定不漂移。

## 决策

**产品形态（Q1–Q13，主开发者裁决）**：
- 音频播放：默认手动点播 + 设置"自动播放"开关（学习节奏由学习者掌控；合成已计费，播放策略不增上游费用）。
- 音色试听：新增计量合成端点（固定短文本 + 可选自定义），BYOK 选音色闭环（"你自己掌控声音"核心需求）。
- 设置页绑定：简化三卡片（默认 LLM / 默认 TTS+音色 / 可选摘要模型，底层写 `*` 绑定）+ 高级折叠完整矩阵。
- 高自定义 WebUI：主题引擎（CSS 变量 + 预设 + 自定义面板）+ 高级 CSS/变量深度定制；**布局拖拽/组件重排永久放弃**
  （长期稳定优先，不入 roadmap）；有界布局感（侧栏折叠/密度/字号/面板显隐）走偏好。
- 偏好**跨设备随账户**（DB user_preferences + REST，符 history 0530 用户级配置仅 DB+webui）。
- 首次使用引导清单（三步：配 LLM→配 TTS+音色→对话，预设一键，可跳过可重入）。
- 会话管理：文件夹组织（见下）；on_disconnect 偏好级全局默认 + 逐会话高级覆盖（明示 continue 消耗额度，P22 硬要求）；
  删除须确认（转录不可恢复）；断线重连=重附持久态（无 mid-run 回放，已定案）。
- 认证：补**自助改密**（验旧密→统一策略→撤销其他会话保留当前）+ 显示名编辑；重置走独立公开页（令牌+新密码，M4 前线下递送）。
- 用量：M1d 仅回合级 usage 脚注（SSE Usage 事件，零后端）；看板 M2。
- 响应式：M1d 含移动视口（侧栏折叠/触控/音频适配），人工验收含真机；PWA 留 roadmap。
- 错误 UX：error 按 code 分流（auth/quota/unconfigured→去设置；retryable→重试；busy→toast；shutting_down→退出提示），
  失败不丢输入文本。音频卡片（播放/进度/回放）+ 词级高亮（live SSE 时间戳 / 回放 meta）；reasoning 默认折叠。

**会话文件夹 = 虚拟路径模型（Q11，主开发者提出，agent 评估采纳并收回原代理 id 方案）**：
- 会话存储扁平，`sessions.path TEXT`（NULL=未分类）存**文件夹链**虚拟路径（如 `/日语/五十音`），路径即身份，
  前端按 trie 渲染；会话以标题（首条用户消息截断，P25）渲染为叶子，**会话名不进 path**。
- **嵌套 M1d 即做**（路径模型下嵌套成本塌缩为 trie 渲染 + 前缀批量改写 + 子串检查，天然无环）；
  收回原"嵌套留 roadmap"与"允许同名"两条推荐——路径身份使同父同名=同一文件夹（Linux 语义），无需 UNIQUE 防重。
- 空文件夹持久：轻量登记表 `session_folders(user_id, module_id, path, UNIQUE(user_id,module_id,path))`
  （path 全 NOT NULL 避两后端 NULL-UNIQUE 陷阱，bindings 哨兵教训）；树=登记表 ∪ 会话路径前缀。
- **模块 chroot**：module 是隐式根命名空间（非用户可见路径段），module_id 创建时固定→构造上杜绝跨模块移动；
  M1 无模块=默认命名空间（哨兵 `default`，新约定入 glossary）；M2 每模块一套树，shell 历史组件按命名空间复用（P25）。
- 操作：移动会话=单行改 path（目标链自动注册）；改名/移动文件夹=Rust 侧前缀改写 + 单事务批量 UPDATE
  （目标不得在源子树内）；删非空文件夹→子会话**上移一层**（确认对话框显示数量，**绝不级联删会话**）。
- 校验（服务端权威，kernel path.rs）：**NFC 归一化**（日语浊音 `が` 单码位 vs `か`+组合符 NFD 视觉同形异码→裂文件夹陷阱）
  + 禁 `/`/控制字符/空段/`.`/`..`/首尾空白；**上限固定常量**（深度≤8、段≤64 字符、全路径≤1024，**不进 config**）。
- **上限稳定性原则**（主开发者疑虑触发）：校验仅作用写入时，已存数据永不回溯失效（渲染按 `/` split 无深度假设）；
  放宽永远安全、收紧才需 grandfather 兼容考量；上限是协议级常量非可调旋钮，兼作稳定性硬边界（限 trie 递归/改写扇出）。
- 编码：DB TEXT+JSON+HTTP 全 UTF-8，存储层乱码是伪问题；真风险=NFC 归一化 + query URL 编码 + 服务端校验。
  前缀匹配在 Rust 侧（不用 LIKE，免 `%`/`_` 转义，守 JSON 整取回 Rust 纪律）。

**技术设计（Q14–Q17）**：
- 类型生成：**openapi-typescript（类型）+ openapi-fetch（客户端）**，生成类型提交入仓库 + **CI freshness diff**
  （类比 gate --check-index）；web/core 配 vitest 脱敏 fixture round-trip 锚定线缆。
- **后端补全 OpenAPI schema（Q17=B，主开发者"不允许漂移"）**：给 5 个 REST-facing kernel-api 类型
  （ModelInfo/VoiceInfo/ChatMessage/WordTimestamp/AudioFormat）加 `utoipa::ToSchema` derive——
  **kernel-api 新增 utoipa 有意耦合**（现声明 axum/sqlx），属契约 crate 变更→**触发契约级全量语义审查** +
  耦合声明更新。serde 线缆形状/trait 签名不变，变更有界。否决 A 方案（手工注入 schema 常量= reintroduce 重复漂移源）。
  SSE SessionEvent/Usage/TtsUsage 不入 OpenAPI（已定案）。auth-local UserInfo + godoword 新 DTO 一并 ToSchema。
- 音频引擎**风险前置 spike**（承 M1a 原则）：AudioContext({sampleRate:24000}) 免重采样 + AudioWorklet 环形缓冲
  + 高亮播放时钟同步；第一实现 phase 先跑通出声+高亮+移动浏览器，再铺 UI。
- 前端分层（history 0330）：web/core 框架无关 TS（api/sse/audio/session/theme/i18n/prefs，vitest 重测）+
  web/shell Svelte 5 runes SPA（组件轻测，视觉人工）；领域逻辑不进组件；不引外部状态库。
- SSE 客户端 fetch ReadableStream + eventsource-parser（POST→SSE，EventSource 不可用）；i18n svelte-i18n zh-CN 首发；
  主题 CSS 变量引擎（无 CSS-in-JS）；路由 history 模式 + axum ServeDir index.html fallback（修 SPA 深链 404）。
- 测试分层：core 重测 + 组件轻测 + 视觉人工（E2E 后置 roadmap）；CI 前端 job lint/svelte-check/build/vitest + 类型 freshness。
- Dockerfile node 多阶段（npm ci→vite build→dist 入运行镜像），重构建走 CI；冒烟增 SPA 伺服+深链断言。

**后端 REST 扩展（Q5，同实施 PR 分 phase，均不动 trait 签名）**：preferences GET/PUT；folders CRUD；
sessions 元数据列表（title/created_at/last_active/message_count/path）+ 移动 path；audio/{id}/meta（回放时间戳出口，
补审计发现的文档—代码缺口）；providers/{id}/preview（试听）；auth/change-password + PUT auth/me。
0005 迁移：user_preferences + session_folders + sessions.path。

## 后果

M1d 设计闭环，实施蓝图入 roadmap（phase P0 落档→P1 音频 spike→P2 后端+契约审查→P3 web/core→P4–P6 shell UI→
P7 构建/CI→P8 验收）。**M1d 含一次有界 kernel-api 耦合变更（utoipa）→契约级全量审查**（修正"M1d 不改后端契约"
旧表述为"不改 trait 签名/协议形状，含 derive 级耦合新增"）。布局拖拽永久放弃。status 按主开发者要求较以往更详细
（phase 级跟踪）。原始讨论记录（仓库外）R1–R15/P25 核心需求核对无丢失；回放高亮缺口（P25 已确认需求）M1d 补齐。
