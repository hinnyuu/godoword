# M2 设计决策（需求驱动六轮讨论定案 + 实施蓝图）

## 背景

M1d 闭环 + 漂移清扫后主开发者发起 M2 设计讨论，要求**从需求与功能性出发、agent 提问多轮至设计臻于完美再开工**。
agent 先审计级全量阅读重建心智模型（docs/wiki/history 63 条/仓库外需求记录/全部源码测试/门禁 CI，基线全绿），
再六轮讨论（R1 产品形态 / R2 学习闭环与评估 / R3 模块 UX 与音频资产 / R4 技术接缝与范围 / R5 评估机制与内容 / R6 前端集成与实施姿态）。
本条目落档全部裁决；实施蓝图见 [roadmap M2 实施蓝图](../docs/project/roadmap.md#m2-实施蓝图)。
主旨延续：以用户实际使用需求为核心、agent 长期工程可行性、重要分歧人工介入、长期稳定不漂移。
**主开发者初步认可，交第三方审计后再反馈**（审计反馈前不启动 P1 实施）。

## 决策

### 产品形态（R1–R3，主开发者裁决）

- **课程形态 = 混合式**：结构化操练卡（模块前端确定性判对错，发结构化进度事件 ExerciseOutcome）+ LLM 教师对话课
  （模块 persona + plan 钉住，转录喂提取报告）。双通道正合既有架构（练习对错 + 涌现证据，history 0900）。
- **T4 决议 = 自由对话改造为 teach-free 轻量教学模块**（非保留无模块态、非退役）：统一注册/plan/命名空间；
  内核 DEFAULT_TEACHER_PERSONA 移入 teach-free；既有无模块会话与 default 文件夹迁入 teach-free；**plan 可选**
  （未 placement 也能自由对话，persona-only，转录仍喂评估）。此选择简化 outbox 路由（事件按 module_id 统一扇出，免 kernel 哨兵特例）。
- **Placement = 自评问卷 + 确定性迷你测 + 可选 LLM 短测**：问卷（水平/焦点/目标）+ ~10–15 题识别迷你测（模块前端确定性判，
  零上游，客观标记已会假名）→ assessor 生成初始方案；可选「精准定级」开 assess 对话短测（TTS 出题）精炼方案。零基础不被迫考试。
- **自适应语义 = 固定教学顺序 + 跳过已会 + plan 驱动侧重**：五十音顺序固定（教学逻辑可预期）；迷你测标记已会跳过；
  plan.focus/weaknesses 驱动复习侧重、引入节奏、教师讲解深度/语言。
- **课时结构 = 一课三段式**：引入对话（讲解+领读+音频）→ 结构化操练卡 → 收尾对话（据操练结果纠错/鼓励）；
  完成发 session-ended（完成语义，转录保留可复习，触发提取）。**完成≠删除**（删除是隐私操作，转录级联删不提取）。
- **操练题型 = 识别 + 听音 + 认读**（v1 无 STT，发音不机器验证）：识别（假名→romaji 多选）+ 听音（静态音频→假名多选）+
  认读（假名→romaji 文本输入）。确定性判定。
- **复习 = 两者都要**：操练选题按 plan.weaknesses/历史错项加权 + 专项复习课（独立课时类型，top-N 弱项）。
- **静态音频 = 构建期 TTS 合成入仓库**：开发者 key 一次性合成全假名 canonical 音频（默认教师音色 longanlingxin），
  **裸 PCM + manifest**（24kHz 16-bit LE，引擎零解码直推，~104 项 ~7.5MB），稳定 asset id，模块路由直供，零 TTS 零等待零用户费用。
- **导航 = 学习仪表盘首页 + /m/<id> 模块路由**：首页模块卡（进度/继续学习/自由对话入口/方案卡）；历史会话组件按命名空间复用。
- **方案可见度 = 方案面板 + 掌握度热力图**：assess UI 示当前方案（水平/焦点/短板人类可读）+ 版本演进（structured 确定性 diff，零额外 LLM）
  + 重新评估按钮；gojuon 假名掌握度热力图（进度事件聚合）；**提取报告内部不原始展示**（LLM 中间产物，噪声/技术化）。

### 评估机制与内容（R5，评估实现专轮，history 0630 预留）

- **内容范围 = 全假名 ~104**（清音 46 + 濁音 20 + 半濁音 5 + 拗音 ~33），数据驱动（课程数据表 + 音频资产，机制与内容量解耦）。
- **提取报告 = 结构化观察条目**：extractor role LLM 读转录 span → 多条 {skill_tag, evidence, outcome_hint, confidence}
  （如「か行听音混淆 き/け」），mod_teach_assess_reports 私有，可聚合可追溯，喂 assessor 精准定位短板。
- **重规划 = 全量再生自动应用**：assessor role LLM 读（当前 plan + 上版以来结构化事件聚合 + 提取报告）→ 全新 LearningPlan
  （structured + teacher_prompt）version+1 自动应用，旧版留存；**并发锁**（已定案）+ 失败保留旧版不固化部分。
- **阈值**：≥20 新进度事件 或 ≥3 新提取报告（可配）自动 + 手动「重新评估」按钮；assessor/extractor 用便宜模型（role 绑定），消耗透明。
- **课时粒度 = 一行/组 ~5 项**：清音按行（あ行 a i u e o），濁音/半濁音按行，拗音按组（きゃきゅきょ ~3）；
  操练 ~5 项×3 题型×2 复现≈30 卡。新授课（下一组，跳过已会）+ 复习课（top-N 弱项）。

### 技术接缝与范围（R4）

- **MVP 范围 = 黄金路径 + 用量看板 + M1c 一致性检查 + 真正再生**；**推迟白名单缓存 + 角色音色档案实体**
  （静态资产已覆盖 gojuon，白名单 M2 无消费者；音色档案无黄金路径消费者，M2+ 方向）——治理克制，不建无消费者基础设施。
- **用量看板 = 聚合面板 + 近期调用**：call_log 按模块/能力/模型聚合 tokens（LLM）/characters（TTS）+ 近期调用列表（时间/状态/latency）；
  示用量数量不示金额（BYOK 各服务商定价不一）。
- **真正再生**：消息 API 演进，再生端点替换失败 assistant 回合（删其后消息，从前驱用户消息重跑），修补 history 1240 重发致重复用户行取舍。
- **契约姿态 = 有界新增 + 契约级全量语义审查**（承 M1d utoipa 先例，trait 签名/协议 serde 形状尽量不动）。

### 前端集成与实施姿态（R6）

- **前端集成 = 运行时懒加载 chunk**（回归契约 FrontendManifest 原设想）：web/modules/<id> 独立入口（export mount(target, services)），
  Vite 多入口 + core 共享 chunk（manualChunks 提取 @godoword/core 单例跨 chunk 共享 api/auth/prefs/audio/sse）；
  module.yaml frontend.entry 指向构建 chunk，shell 路由 /m/<id> 动态 import→mount。模块前端真隔离，仍可整重写（重编译）。
- **实施姿态 = 风险前置垂直切片**（承 M1a）：P1 先最薄模块集成切片（注册表 + ModuleContext + 回合接线 + teach-free）
  跑通模块会话端到端（契约新增此 phase 落 + 全量审查 + 二审），再铺 assess/gojuon。

### 技术设计（agent 工程提案，主开发者初步认可，待第三方审计）

- **kernel 模块注册表**：module.yaml 运行时反序列化（ModuleKind 补 Kernel 变体）+ cargo feature 注册 + 迁移编排
  （kernel 0001–0006 → 模块注册序，版本键 mod_<id>_NNNN 全局唯一）。
- **ModuleContext 实现 + 有界契约新增**：落地 store/emit_progress/current_plan；新增 `llm(role, ChatRequest)->ChatStream`
  （kernel 按 user+module+cap+role 解析绑定解密调适配器，全计量 call_log，模块永不触 key/上游）+ `complete_session()`
  （完成≠删除）；模块服务注入取 **ctx 工厂**（契约 trait ModuleContextFactory::for_session/for_user，组合根构造期注入，routes() 签名不动）。
- **回合循环接线**：向模块取 persona；plan.teacher_prompt 钉住版本（sessions.plan_version 落地，resume 取当前 Q30）；
  模块工具分发（speak 仍 kernel 统一）；on_session_start/end；绑定解析带 module_id（现硬编码 None）。
- **outbox 扇出 + 幂等（A5）**：dispatch 按 consumes_events 扇出到订阅模块（assess 订阅 gojuon/free/kernel）；
  kernel 级 event_consumptions(event_id, module_id, processed_at) per-subscriber 投递表（成功不重投，失败留待）；handler 仍建议幂等。
- **kernel 0006**：progress_events 补 outcome/item_ref/difficulty 列（契约 ProgressEvent 已有字段，DB 对齐）+ OutboxEvent 取回 created_at；
  sessions 补 completed_at。
- **plan structured.extra** 承载 gojuon 专属 {known_kana, mastered, current_group, pacing}（全局 plan + 模块解释 extra）。
- **teach-assess 私有表** mod_teach_assess_*：plans/reports/事件聚合；**teach-gojuon 私有表** mod_teach_gojuon_*：item_progress/lessons。

### 风险/行动项

- **DashScope 输出权利条款**：静态音频入 AGPL 仓库前须主开发者确认生成音频可再分发（P4 前置）。
- 懒加载 chunk 共享态桥接需 P1/P5 spike 验证（core 单例跨 chunk + mount 契约）。
- ~104 音频构建期合成脚本（开发者 key，可重跑，资产入仓库）。
