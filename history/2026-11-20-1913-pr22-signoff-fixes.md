# PR #22 人工 sign-off 轮：滚动信号补全 + 回合超时归用户级（默认 180s）

## 背景

主开发者对 PR #22 前端视觉残留做 PC+移动端双侧 sign-off（PR 评论记录）：⏹ 真停止 ✔、删除先确认 ✔、
暗色横幅 ✔（借长回复触发的硬超时错误验证）。两项发现：
①近底自动滚动跟随正文但**不跟随思考内容（展开折叠亦不）与音频台词**——不确定是否符合预期；
②长回复多次触发「回合硬超时」（120s 默认）。

## 决策

- **滚动信号补全（实现遗漏，非预期行为）**：O10 自动滚动原仅跟踪 messages.length + 末气泡 text 长度，
  漏 reasoning 增长/segments.words 词数/showReasoning 展开——三者皆气泡内流式内容，应跟随。
  信号扩为 `长度:正文:思考:词数:折叠态`，近底守卫不变（手动上滚不打架）。
- **回合超时归用户级（主开发者裁决，默认 180s）**：agent 原提案部署级可配，主开发者质疑「为什么不由
  BYOK 用户自己配」——讨论后采纳用户级：超时本质是 **BYOK 成本/耐心权衡**（烧自己的额度），与
  on_disconnect（cancel 省费/continue 花费）同轴，后者已是用户级；部署级资源保护论点已被既有守护覆盖
  （detach 并发上限 4 + 上游 read 超时 30s + 工具迭代上限 8），另设部署旋钮边际收益小（治理克制）。
  落 `Preferences.turn_timeout_secs`（kernel 类型非 kernel-api，**不触发契约变更**；SessionParams 方案
  会动契约 serde 形状，否决）。Runtime 每回合读偏好解析生效值，**钳位 [30,3600]** 防误配
  （0=即时超时/巨值=守护失效）；读失败 fail-open 到默认（warn 留痕）。默认 120s→**180s**。
  硬边界语义不变（超时 abort + try_send 终态 + 释放活跃锁，C6/R3/N6 锚定不动）。
  设置页偏好面板数字输入（30–3600，hint 明示额度保护语义）+ i18n。
- **OpenAPI 再生**：Preferences 新键 → 本地起服务 dump openapi.json + openapi-typescript 再生 schema.d.ts
  （freshness CI 锚定；实验服务/临时卷/日志用后即清）。
