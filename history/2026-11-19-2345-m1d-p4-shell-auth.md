# M1d P4 实现：shell 基础 + 认证/管理/引导 UI + core 服务层

## 背景

P3 web/core 领域核心后推进 P4 shell 视图层（认证/管理/引导）+ core 服务层（shell 调域函数）。
承 history 0330 领域逻辑不进组件。设计依据 history 2049。

## 决策（实现要点）

- **core 服务层**（api/services.ts）：auth/admin/sessions/folders/providers/bindings 全域函数（封装 openapi-fetch +
  CSRF header param + ApiError 状态归一）；shell 组件调这些函数不裸调 api。类型由生成 schema 派生（UserInfo/Provider/Binding/Folder/SessionListItem 等）。
- **OpenAPI IntoParams 修复**（P3 类型生成暴露）：SessionListQuery/FolderQuery utoipa IntoParams 默认 parameter_in=Path
  误标 path required → 加 `#[into_params(parameter_in = Query)]` 修正为 query optional；再生 openapi.json + schema.d.ts。
- **shell 基础**：svelte-i18n 注册 core zh-CN catalog；runes 模块 store（auth.svelte.ts 用户态/login/logout/register/isAdmin；
  prefs.svelte.ts 加载偏好+应用主题/自定义 CSS/字号+update 保存）；svelte-spa-router hash 路由（静态伺服深链稳健，免 server fallback）；
  App 认证门（未登录受保护路由跳登录）+ 导航 + 401 钩子 + AGPL 页脚。
- **Svelte 5 runes 自动检测**：svelte.config 不强制 runes:true（svelte-spa-router legacy API 与强制 runes 冲突）→
  自动检测（shell 组件 runes / legacy lib legacy 模式）。
- **页面**：Login/Register（密码策略提示）/Reset（公开令牌页）/Admin（用户列表+禁用启用守卫+邀请码生成+重置令牌）/
  Onboarding（三步清单：LLM/TTS/对话，按 provider+binding 配置态勾选）；Home/Settings/Sessions 占位（P5/P6 填充）。
- **验证**：core tsc + vitest 32 绿；shell svelte-check 0 错误 + vite build 绿（171 模块）。浏览器认证流人工确认待测。

## 后果

shell 认证/管理/引导 UI 就绪（hash 路由 + i18n + 主题应用 + 认证门），core 服务层封装 api 细节。
OpenAPI query 参数契约修正（IntoParams）。P5 设置 UI（provider/绑定/试听/主题面板）→ P6 会话 UI（对话/文件夹树/音频/高亮）→
P7 构建/CI → P8 验收。详见 [status](../docs/project/status.md)、[architecture 前端节](../docs/project/architecture.md#前端m1d-起)。
