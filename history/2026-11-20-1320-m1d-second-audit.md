# M1d 审计修复轮二审（修复代码自身审计 + 一审盲点补漏）

## 背景

主开发者复验通过新增 UI 面后，要求按一审严格程度二审（避免一审遗漏）。二审 focus 一审修复**引入的新代码**
（一审审计的是旧代码，修复自身未经审计）+ 一审观察项再裁决 + 修复间交互 + 边界校验遗漏。
制度依据：conventions「设计方向级审查须趁上下文仍在做二审复核（一审自查难免盲点）」。

## 决策（二审发现与修复）

- **R2-1 prefs 串行队列快照时机 bug（一审 M5 修复引入，真缺陷）**：update 的 `{...this.prefs,...patch}`
  在**调用时**取快照而非队列执行时——连续快速 toggle 第二个 patch 基于旧态，丢前序变更。
  修复：快照移入队列闭包（执行时取最新态）。
- **R2-2 create_folder 返回构造近似行**：时间戳与事务内落库值微秒级不一致。修复：返回 get_folder 落库行。
- **R2-3 username 首尾空白陷阱**：validate_username 仅 trim 校验但存储不 trim——" admin" 与 "admin"
  视觉同形异码（同路径 NFC 教训）。修复：拒绝首尾空白 + 负例。
- **R2-4 provider 输入边界缺失**：adapter_id 任意字符串/空 key/非 http(s) base_url 静默接受。
  修复：adapter 须已注册（llm.id/tts.id）+ label/base_url 非空 + http(s) scheme + key 非空（更新留空保留）→400；
  update_provider 预检归属 + 沿用既有 adapter 校验；handler 级负例测试。
- **R2-5 音频资源/定时器泄漏**：ChatView 卸载未清 toastTimer/未 dispose AudioContext；Settings 试听引擎同。
  修复：onDestroy 清理（ChatView 另中止在途回合）。
- **R2-6 auto_play 异步窗口竞态**：init/play await 期间 isPlaying 尚 false，两段 audio-end 可并发 playSeg 交错。
  修复：playPending 守卫（try/finally 复位）。
- **R2-7 BYOK 转发面威胁模型入档**：base_url 用户自填服务端按址转发（SSRF 面）——私有部署邀请制信任边界内
  风险接受（architecture 安全节明示），公网多租户（M4 OIDC）再议；输入边界校验 + 超时为既有缓解。
- **杂项**：Settings 删 provider 误用会话删除确认文案→专属 providerDeleteConfirm（级联删绑定警示）；
  Sidebar 隐式文件夹删除 no-op→先登记再删（与改名一致）；folders.rs 并发写 TOCTOU fail-closed 语义入模块注释；
  update_provider OpenAPI 补 400 + 快照再生。

**一审观察项再裁决（维持不修，理由留档）**：folder 写并发 TOCTOU（单用户产品，UNIQUE/回滚 fail-closed 无损坏）；
list_sessions_meta O(消息量)（私有规模有界，M2 看板再优化）；retry 重复用户行（history 1240 取舍，再生语义 M2）；
streamTurn 裸 fetch 401 不触发登录钩子（下次任何 API 调用即跳转，可恢复）；preview 错误路径 partial usage 不计量
（与 LLM 错误路径计量模式一致）；live 合成失败段 ▶ 永久禁用（无完整音频不可回放，语义正确）。
