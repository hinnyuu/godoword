# M1 拆分蓝图：四子里程碑 + speak 契约落点 + 开发态回归机制

## 背景

M1 前置（存储契约 C + CI 缺口闭合 + agent 交接）合并后，主开发者授权详细规划 M1 拆分。
agent 全量探索项目（契约 trait/类型、Round 1 API 实测事实、P12–P25 设计决策、CI/冒烟/Dockerfile
集成点）后给出蓝图 v1，主开发者认可拆分与多数设计点，追加两条约束：①开发态临时取舍只起
临时开发测试作用，之后必须回归规范；②speak 落点值得专门讨论一轮（未来使用 speak 的模块众多）。
主旨定调：**首要考虑项目长期维护的稳定性、防止漂移，工时与时间成本次要**。

## 决策

**拆分**：M1 拆 M1a–M1d 四子里程碑，垂直切片先行。M1a 适配器（llm-openai + tts-qwen-audio）
+ kernel 最小回合循环 + SSE 出声（无持久化/无认证/无 UI），前置验证最高集成风险
（qwen 流式归一化 + DashScope TTS 音频管线 + SSE 协议 + speak 回合）；M1b kernel 存储基底
+ 加密 + 绑定 + 配置 + 自适应降权/部署初始化；M1c 会话运行时接基底 + auth-local + 管理员重置；
M1d Svelte 骨架 + 设置/会话/认证 UI。无 UI 阶段仅自动验收（CI + 本地真 key 脚本），
完整人工感官验收只在 M1d。每子里程碑内部再分执行 phase，status 持续维护供上下文耗尽交接。

**speak 落点（决策 A）**：speak 规格落 kernel-api 契约层，新增 SPEAK_TOOL_NAME 常量 +
SpeakArgs 类型化结构（LLM 可控子集 text/voice/rate/pitch/instruction/language_hints；
model/format/sample_rate/word_timestamps 由 kernel 从绑定/配置填，不暴露给 LLM）+
speak_tool_spec() -> ToolSpec + 黄金测试锚定 spec↔SpeakArgs。kernel 运行时反序列化
arguments→SpeakArgs→合并绑定→TtsRequest→TtsProvider 执行。理由：speak 是众多教学模块共用面，
置契约层使演进触发全量审查防漂移，与 TtsRequest 代码锚定防分裂；模块虽不实现 speak 但依赖其形状
（persona/前端渲染）。否决 kernel 内部常量（省工时但绕过契约审查、易与 TtsRequest 分裂，与主旨相悖）。
此为契约新增，M1a 执行时走全量 docs+wiki 语义审查；修订 contract.md "kernel 定义"措辞与 P26 对齐。

**零返工接缝**：kernel 内部（非契约）SessionRepo/BindingResolver/AudioCache 三 trait，
M1a 内存/env impl 作生产默认（临时态），M1b/c 换 DB/文件系统 impl，回合循环不重写。
内存 impl 作测试替身长期保留（永久架构非债务）。

**bindings 默认哨兵**：module_id 默认用哨兵 `*` 取代 NULL——UNIQUE(user,module,cap,role)
在两后端 NULL 皆互不相等致默认绑定唯一性失效；哨兵使 UNIQUE 正常约束、解析一致。M1b 同步 architecture。

**开发态回归机制**：临时取舍逐项登记（T1 dev 旁路→M1c 删除；T2 内存生产默认→M1b/c 换实装；
T3 root 运行→M1b 降权；T4 默认教师模式→M2 决议）。dev 旁路装 cargo feature dev-bypass，
release Dockerfile 永不启用（硬隔离）；代码 `// DEV-DEBT: T<n>` 标记可 grep；status 登记每里程碑
验收核对逾期阻塞；回归 PR 强制断言；CI 守卫 release 路径无 dev-bypass。

**其他**：M1a dev 旁路 env GODOWORD_DEV_LLM_KEY/TTS_KEY + 固定 dev user；fixtures 重录
（M1a 首任务，本地真 key 录脱敏 LLM/TTS 响应，CI 永不用真 key）；OpenAPI 随 M1a/b/c REST 落 utoipa、
M1d 生成 TS，SSE 不入 OpenAPI；M1 无教学模块，回合循环用 kernel 默认教师 persona。

## 后果

M1 有了风险前置、零返工、验收分层、上下文耗尽友好的实施基石，蓝图入 [roadmap](../docs/project/roadmap.md#m1-拆分蓝图)
单一来源。speak 成为版本化契约面，演进受全量审查保护。开发态取舍从引入起有回归里程碑 + 机械守卫，
不静默漂移成永久后门。下一步 M1a 启动（首任务 fixtures 录制）；speak 契约新增的全量审查在 M1a 执行。
