# kernel-api（模块契约）

这是 godoword 的"接口说明书"。所有适配器与教学模块都只依赖它，彼此不直接往来。
这样任何一个模块出问题，都可以照着这份契约整体重写，而不牵连其他模块。

契约还定义了共用的 speak 语音工具规格（M1a 起）：所有教学模块的 LLM 老师都经它统一调用语音合成，
规格改动会触发全量文档审查，防止各模块各自假设而漂移。

开发者向的精确 trait 定义见 [docs/contract.md](../docs/contract.md)。

M1d 起契约还承担前端类型生成的单一事实源：REST 用到的共享类型（模型/音色/聊天消息/词级时间戳/音频编码）
派生 OpenAPI schema（utoipa 有意耦合，与 axum/sqlx 并列），前端由此生成 TypeScript 类型，防前后端契约漂移。

M2 P1 起契约新增模块受控服务面：教学模块经 `ModuleContext` 使用内核能力——LLM 调用由内核中介
（模块不接触 key/上游，用量按模块归因）、会话完成语义（完成≠删除，转录保留）、白名单缓存合成
（标准音频一次生成永久使用，存持久资产区）。`ModuleContextFactory` 在构造模块时注入，
分会话级/用户级两种上下文（用户级无会话，需会话的操作会明确报错）。进度事件信封新增难度字段（旧数据兼容）。
